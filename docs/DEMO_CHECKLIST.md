# Mini AI Knowledge Assistant — Live Demonstration Checklist

This document provides a practical, step-by-step checklist for conducting a live demonstration of the Mini AI Knowledge Assistant (Mini AKA).

---

## 1. Pre-Demo Environment & System Verification

### Prerequisites & Credentials
- [ ] Confirm Python 3.9+ and Node.js environment are available.
- [ ] Set `GEMINI_API_KEY` in environment (or `.env` file) for live LLM generation:
  ```bash
  export GEMINI_API_KEY="your-api-key-here"
  ```
  *(Note: If no API key is provided, the system seamlessly operates in **Evidence-Only Mode**, returning verified passage sources without LLM generation).*

### Starting Backend & Frontend
1. **Start FastAPI Backend**:
   ```bash
   uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
   ```
2. **Start Vite Frontend**:
   ```bash
   cd frontend
   npm run dev
   ```
3. **Verify Connectivity**:
   - Open `http://localhost:5173` in a web browser.
   - Confirm top header displays status: **Connected** / **Ready** (or **No Documents**).
   - Verify `/api/health` returns status `ok`:
     ```bash
     curl http://127.0.0.1:8000/api/health
     ```

## 2. Step-by-Step Live Demonstration Flow

### Step A: Document Library Overview
- Select the **Library** tab in the top navigation.
- Point out the clean editorial document inventory table.
- Demonstrate initial empty library state (if starting fresh) or existing indexed domain documents.

### Step B: Uploading & Indexing a Technical Document
- Click **Upload Document** (or **Add your first document**).
- Upload one of the repository technical domain PDFs from the project root:
  - `campus_resource_management.pdf`
  - `edge_computing_iot.pdf`
  - `predictive_maintenance_ml.pdf`
- **Highlight**: Observe real-time Server-Sent Events (SSE) trace progression:
  1. `DOCUMENT_RECEIVED` (File received & hashed)
  2. `TEXT_EXTRACTED` (Page text extraction)
  3. `TEXT_CLEANED` (Boilerplate/header removal)
  4. `CHUNKED` (Token-aware passage chunking)
  5. `EMBEDDED` (BGE vector embedding computation)
  6. `INDEXED` (Atomic FAISS index persistence)
  7. `COMPLETE` (Registered in document inventory)

### Step C: Grounded Inquiry & Citation Verification
- Switch to the **Inquiry** tab.
- Submit an **in-scope technical query** grounded in the uploaded document. Examples:
  - *"What is the policy for room booking cancellation?"*
  - *"What are the key components of the edge computing gateway architecture?"*
- Observe the response presentation:
  - **Grounded Answer**: Concise answer generated by the LLM (or Evidence-Only notification).
  - **Verified Sources**: Cards displaying exact document name, page number, section index, cosine similarity score, and exact quoted text snippet.
  - **Citation Badges**: Numerical citation tags `[1]`, `[2]` mapping directly from answer claims to source passage cards.

### Step D: Inspecting Retrieval Trace & Provenance
- Switch to the **Trace** tab (or click the Trace counter badge).
- Review the execution timeline for the inquiry:
  - `QUERY_RECEIVED` -> `RETRIEVAL_STARTED` -> `RETRIEVAL_COMPLETED` -> `GATE_EVALUATED` -> `CONTEXT_BUILT` -> `GENERATION_COMPLETED`.
- Click on any trace row with expandable details to view raw metrics (similarity scores, elapsed milliseconds, gate decisions).

### Step E: Testing Out-of-Scope Abstention
- Return to the **Inquiry** tab.
- Click **New Inquiry**.
- Submit an **out-of-scope query** completely outside the domain corpus. Example:
  - *"What is the recipe for baking chocolate chip cookies?"*
  - *"What was the stock price of Apple in 2020?"*
- **Highlight**: Point out the clean **Knowledge Base Abstention** alert:
  - Explains that the document library does not contain relevant information to answer the question.
  - Demonstrates that the similarity threshold (`RELEVANCE_THRESHOLD = 0.67`) successfully prevented hallucination.
  - Click **Inspect sub-threshold passages** drawer to show candidates evaluated below threshold.

## 3. Error Recovery & Resilience Procedures

### Handling Upload Failures
- **Encrypted / Password-Protected PDF**: Displays clean warning *"PDF document is encrypted or password-protected"*.
- **Scanned PDF (No extractable text)**: Displays clean message *"No extractable text found in PDF. Scanned PDFs require text extraction or OCR."*
- **Oversized Upload**: Server rejects files exceeding configured maximum size with clean status message.

### Handling Query / Network Failures
- **Backend Offline**: If the backend process crashes or goes offline, the top header status indicator changes to **Offline**, a connection warning banner appears in the Inquiry tab, and the question composer is safely disabled.
- **Provider / Network Errors**: If an API provider error occurs (`PROVIDER_UNAVAILABLE` or `NETWORK_ERROR`), a **Retry Inquiry** button appears directly within the error alert box, allowing immediate one-click query retry.
- **Interrupted Stream**: If the connection drops mid-stream, the stream parser catches the interruption gracefully without leaving the interface permanently spinning.
